# LiteCut 已知问题与修复记录

- 验收时间：2026-10-20；线上前端 https://litecut.vercel.app，后端 livecraft-media（0.4.2 → 0.4.3）

## 已修复并回归验证

### FIX-1平台识别可被 userinfo 混淆链接绕过（SSRF 面）
- 现象：`https://v.douyin.com@127.0.0.1/admin` 因整串 URL 正则命中 "douyin.com" 被误判为抖音链接，进入服务端抓取管道（实测 extract_failed，耗时 4.08s）。
- 根因：后端 `detect_platform` 对原始字符串做正则，未解析真实主机名。
- 修复：改用 `urlsplit().hostname` + 「主机名等于平台域名或以 `.域名` 结尾」判断；同时收紧仿冒域名（notdouyin.com、douyin.com.evil.com 均拒绝）。后端版本 0.4.2 → 0.4.3。
- 回归：单元用例 13/13（四平台合法形态 + 混淆/仿冒/元数据/不支持平台）；线上回归 SEC-U2、SEC-U3 返回 unknown_platform，DY-V1、TT-V1、DY-A1 解析不受影响（5/5）。

### FIX-2全局导航绝对化表述与事实不符
- 现象：站点级导航长期显示「纯本地 / 免上传 · 零等待 · 100% 隐私安全」，而招牌工具（去水印解析）需将链接发送至云端后端处理。
- 修复：改为「本地处理 / 视频本地处理 · 解析走云端 · 隐私安全」。工具级 `isLocalOnly` 标记本就准确（解析工具为 false，徽章不展示），解析页内也有云端披露，本次仅修正全局文案。
- 回归：新构建已部署，线上 bundle 校验含新文案。

## 仍然存在的 Bug / 问题

### KI-1前端宣称支持 B 站、微博，后端不支持
- 前端平台表包含哔哩哔哩、微博，用户粘贴即得 unknown_platform。属文案与能力不一致，易被用户视为「功能坏了」。
- 建议（二选一，需产品确认，未在本次擅自修改）：从前端平台表移除/标注「暂不支持」，或后端补齐实现。

### KI-2小红书解析不可用
- 真实短链实测 extract_failed。小红书对匿名抓取风控严格，通常需登录态 Cookie；本项目不绕过登录与访问控制，故当前无合规解法。建议界面对小红书给出明确预期提示。

### KI-3快手真实内容链接未验证
- 平台识别、非内容链接拒绝行为正确；但未取得可验证的真实快手内容短链（未用伪造链接充数），其内容解析能力未知。待补充真实样本后补测。

### KI-4极小文件压缩后体积反而变大且无提示
- 实测 fixA（33,757 B）压缩输出 44,791 B。重编码固定开销导致，属算法特性，但产品未做「输出未变小」提醒。建议：输出 ≥ 输入时在结果区给出提示。

### KI-5桌面 Chrome 保存对话框路径未真机验证
- 本地工具在桌面 Chromium 走 `showSaveFilePicker` 原生保存框；无头自动化无法完成该路径，本次以 Blob 回退路径（iOS/Android 同路）完成验证。若个别 WebView 中该 API 存在但行为异常，可能影响保存（代码已有 try/catch 回退 Blob）。

### KI-6解析失败原因对用户不可区分
- 无效链接、已删除内容、平台风控统一收敛为 extract_failed 与同一句文案，用户无法判断是链接问题还是服务问题。建议后端按落地页状态细分错误码。

### KI-7后端冷启动慢
- Render 免费版休眠后冷启动约 24–60s，首次解析明显变慢；前端已做一次自动重试。付费实例或保活可解，属成本取舍。

### KI-8备用解析依赖公共演示服务
- 抖音视频主提取路径在当前风控下不可用，实际成功依赖 api.douyin.wtf 公共演示账号（共享配额、间歇限流）与 tikwm，无 SLA。这是全站可用性的最大单点外部风险。
