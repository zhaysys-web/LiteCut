# LiteCut 性能与环境报告

- 验收时间：2026-10-20
- 线上数据：经生产域名实测（curl，沙箱出口，含代理开销，仅供参考）。
- 工具性能环境：无头 Chromium（Playwright）+ 本地 `vite preview`，与线上为同一 dist 构建（主包哈希/字节数与线上逐一核对一致）。**沙箱可用内存一度仅约 0.5GB 且无 GPU 硬件解码，视频预览为软件渲染，绝对耗时显著高于真实设备**；同一工具在环境健康时（本项目早前轮次）2 秒 360p 素材全流程约 2–4 秒。以下耗时应理解为「受限环境下限参考」，不代表用户设备表现。
- 未覆盖环境（不冒充）：iPhone 真机、Android 真机、Safari/WebKit 引擎（Playwright WebKit 在沙箱内安装失败）、Windows Edge（与 Chromium 同内核，未单独执行）。区分说明：本文所有「通过」均为自动化模拟结论；真机结论仅 Des 按已交付的 iPhone 测试步骤验证后成立。

## 稳定性

- **任务取消**：处理中出现「取消处理」按钮，点击后界面回到空闲态；取消后对同一文件再次处理成功（引擎自动重载）——通过。
- **连续处理内存**：整轮多工具连续运行 JS 堆在 2–13MB 区间波动，无单调增长；结果 Blob 的 Object URL 在下载后 60s 释放，代码审计未见系统性泄漏。
- **环境事件（如实记录）**：在可用内存约 0.5GB 的时段，720p 素材的页面预览（软件解码）曾使无头标签页崩溃一次、GPU 进程 CPU 打满。这是测试环境容量问题，未复现为产品缺陷；真实设备为硬件解码，不适用此结论。进度显示在各工具中与真实进度回调一致，未见假进度。

## 下载机制说明（与环境相关）

本地工具的保存走 `downloadFileSafely`：桌面 Chromium 优先 File System Access（`showSaveFilePicker`，真实用户会看到原生保存对话框）；无头自动化中该 API 无法完成，故自动化验证采用与 iOS Safari / Android 相同的 Blob 回退路径，7 个工具下载均真实落地并校验。桌面 Chrome 真实保存对话框路径未在真机/真实桌面验证（自动化限制），列入未覆盖项（KI-5）。
